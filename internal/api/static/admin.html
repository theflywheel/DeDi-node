Child nodes

A child node is a separate node — its own identity key, its own database, its own log — holding a namespace this one delegates to it. That is a different thing from a replica and from a witness, and worth keeping straight:

ReplicaWitnessChild
Identitythis node's keya stranger's keyits own key
Logthis log, copiedits own, unrelatedits own, delegated
Buys youuptimetamper evidencea namespace someone else runs
This node never holds the child's private key. It issues a one-time enrolment offer; the child generates its own key on first boot and enrols by presenting the public half. A parent that had held the private key could forge the child's checkpoints forever, and the child's log would then prove nothing you had not already asserted yourself.

Roles are not exclusive. Witnessing composes with any of them — a child is normally witnessed by its parent, and a standalone registry can be replicated and witness a peer — so it is a field below rather than a sixth choice.

delegate a namespace

Membership is fixed at bootstrap. Configure the whole set together and tick the box on exactly one member, on its first start only — this daemon bootstraps a configuration and has no way to add a member to a running cluster.

Every member needs the same key file and the same origin. One that generates its own key is not a replica but a second node claiming the first one’s name; one signing under its own origin breaks the set’s single-origin invariant the moment leadership moves to it.

The verifier key is public by construction. Getting it from the target over an unauthenticated channel proves the connection, not the target.

The namespace must sit exactly one level under this node's — you can only delegate what you hold.

Revocation otherwise travels only as fast as caches expire. A subscriber registered here is told the moment a record changes — but the push carries only which entry changed and its sequence number, never the payload. It is a signal to re-read and verify, not something to act on. Consumers should keep checking the log; this only stops them waiting.

Who serves

The directory can answer discovery, not only trust: not just what key does this subscriber use, but who serves retail. Revocation therefore has a second meaning here — a revoked participant stops being returned as somewhere to send business, not merely as somewhere whose signature verifies.

This searches every namespace this node will answer for, not only the one selected above, and narrows by registry name. That is what discovery means — a caller asking who serves a domain has no namespace in mind — so the namespace each result came from is in the table.
