DeDi Node

A self-hostable server for the DeDi standard, with an append-only Merkle log underneath: signed checkpoints, inclusion and consistency proofs, and other nodes witnessing that the log was never rewritten. It is a Merkle log, not a blockchain. New here? Start with the overview, then the quickstart.

API

The read routes, relative to this node. Plain GET, no auth. Every route, its parameters and its errors: API.

EndpointReturns
/dedi/lookup/{namespace}/{registry}/{record}the current version of a record
/dedi/lookup/{namespace}/{registry}registry metadata and schema
/dedi/lookup/{namespace}namespace metadata
/dedi/query/{namespace}[/{registry}]a filtered, paginated listing; ?domain= for who serves a domain
/dedi/versions/{namespace}[/{registry}[/{record}]]full version history
/dedi/log/checkpointsigned tree head (C2SP checkpoint)
/dedi/log/proof/consistency?old=&new=append-only proof between two tree sizes
/dedi/log/historycheckpoints and writes over time
/dedi/witness[/{origin}]what this node has verified about other logs
/dedi/delegations/{namespace}child namespaces delegated, and their witness verdicts
/dedi/networkpeers, reachability, witness health, cluster state
/dedi/statsrequests served, by status class, plus uptime
/.well-known/dedi.index.jsonsigned DeDi manifest; files under /dedi-files/
/healthz, /metricsliveness for probes; Prometheus metrics

Lookup modifiers: ?proof=inclusion attaches a Merkle inclusion proof and the signed checkpoint it verifies against; ?version_id= pins an exact version; ?as_on= resolves the record as of a date (YYYY-MM-DD, the close of that day in UTC) or an RFC 3339 timestamp. Unknown or repeated parameters are a 400, never silently ignored. Example against the public node (on your own node, use your host and a record you published):

curl -s "https://dedi.beckn.try-dough.com/dedi/lookup/bpp.example.com/subscribers.beckn.one/76EU7ofwRCF1aobQkShARrf1PAUsNpHqWUJoynPu9w45YFKmzqaPmy?proof=inclusion"

/dedi/network reports whether configured peers answered. That is an observation, deliberately weaker than witnessing: reachability says a node replied, while a witness verdict is evidence that a log has not been rewritten. Raft replicas of one node share its key and prove nothing about each other; see replication. Witness verdicts are published at /dedi/witness; the _witness namespace that stores them is hidden from the directory browser and the standard's read routes.

Getting registered

Onboarding is operator-gated: there is no self-service registration, by design — who exists on a network is a governed decision, and every onboarding or revocation is an auditable entry in the transparency log. To register a participant on the networks served by the reference nodes, email contact@theflywheel.in with your subscriber id, type (BAP, BPP, BG or CDS), namespace, and Ed25519 signing public key. Details: governance.

Run your own node

One container and one Postgres. Needs Docker; no source checkout and no Go toolchain.

docker network create dedi-net
docker run -d --name dedi-pg --network dedi-net \
  -e POSTGRES_USER=dedi -e POSTGRES_PASSWORD=dedi -e POSTGRES_DB=dedi postgres:16-alpine
docker run -d --name dedi-node --network dedi-net -p 8080:8080 \
  -e DATABASE_URL='postgres://dedi:dedi@dedi-pg:5432/dedi?sslmode=disable' \
  -e DEDI_ORIGIN=localhost/log flywheelai/dedi-node:latest
curl -s localhost:8080/dedi/log/checkpoint   # your own signed tree head

The node mints its identity key on first start and prints the public verifier key in its log. Opening the write plane and making a first signed write: quickstart. Every setting: configuration. Witnessing, anchoring and replication: deployment modes.

Protocol & references

  • LFDT DeDi specification: the Decentralized Directory protocol this node implements, at the pinned commit (dedi.global is the hosted platform)
  • dedi-conformance: the conformance suite, runnable against any DeDi server
  • Beckn protocol · beckn-onix: the adapter whose dediregistry plugin (pkg/plugin/implementation/dediregistry) this node serves, proven over the wire
  • C2SP tlog-checkpoint · C2SP signed-note: the checkpoint and signature formats
  • RFC 6962 (Certificate Transparency): the Merkle tree proofs; implemented via Go's golang.org/x/mod/sumdb/tlog
